# 逆向拆解一条参考片

## R — 原文

> "结构是「一个人 + 一座省的物产清单」：先用反差钩子（古人拿手机自拍）抓注意，然后用「体育—生态—历史—科技—美食」五连击把四川的资源做成快节奏清单，最后落账号引导（关注四川文旅）。每段都给一个具体画面证据（火炬、熊猫、青铜器、火锅），不靠解说堆形容词。"
>
> —— `01_四川/四川拆解报告.md` §三 叙事结构

> "（画面不是实拍：以上是画面里的光影，用于写生成提示词，不是拍摄方案）"
>
> —— `01_四川/拆解视频的提示词.md` §二 画面基准

## I — 自述

拆解不是写影评，而是把一条已经成立的片子还原成一张**可回查的施工图**。它固定输出十块内容：结论、角色与场景、叙事结构、分镜表、剪辑包装、声音、画面测量、复刻要点、不确定点、产物索引。

其中三块最容易漏、也最决定后续质量：
1. **分镜表**必须逐镜给出时长、景别、机位、制作方式、置信度、叠加层、转场——这是后面写提示词的唯一依据。
2. **画面测量**要把"看着挺暖"变成可写进提示词的数字：景别配比、固定/移动机位比例、主光方位、光比、色温、调色倾向、每分钟刀数与平均镜头时长。
3. **不确定点**必须单列。工具对"实拍还是 AI"的判断普遍不稳（本批样本置信度 0.476–0.686），低于阈值就要标 ⚠ 并交人工看图，绝不能当结论用。**但人工看图也会错**：核验发现 `01_四川`、`02_南京`、`21_襄阳` 三次人工修正都恰好推翻了正确结论，因为 2026 年的 AI 人脸已能骗过观感。判定时先找画面内的 AI 标识、水印、致谢字幕——这类证据的优先级高于像素统计和目视观感。

这条不光有案例，还有可复算的数。27 篇原始拆解里，人工改写工具结论共 **7 次，命中 3 次**：

| 改写依据 | 次数 | 结果 |
|---|---|---|
| "看起来像不像真人"（01 四川、02 南京、21 襄阳） | 3 | 0 对，3 错 |
| "这片是什么类型的东西"（09 是动画、11 是影视 IP 角色、18 自带 AI 声明） | 3 | 3 对 |
| 混合判断（20 江西） | 1 | 部分对 |

差别在于：观感是**关于像素的猜测**，类型特征是**关于内容的事实**。要推翻工具，拿后者，别拿前者。

核心心态：**宁可写"判不准"，也不要给一个漂亮但错的结论**——错误结论会被下游的提示词放大成整条片子的返工。

## A1 — 应用示例

**原片案例（01_四川，作者亲历拆解）**：68.5 秒、14 个镜头、720×1280。拆解得到平均镜头 4.89 秒、每分钟 11.4 刀、近景 58%/中景 42%、固定机位 72%、光比约 1.3:1、色温 3000–4000K；包装层统计出字幕 46 句、花字 3 处、文字标注 60 处、贴纸 1 处、常驻图层 2 个；并明确记录 3 处"按台词定位"的卡点。这些测量值全部准确。

但作者把工具判的「96% AI」人工修正为「真人实拍」，**这个修正经原片抽帧核验是错的**：画面右下角常驻「百度 AI生成」水印，20s 处有「由（百度搜索AI视频特效）提供技术支持」，1.5s 画面文字标着「AI 杜甫」。工具判对了，人工按观感改错了。**结论：修正痕迹要留（这点作者做对了），但修正本身必须有画面内证据支撑，不能靠"看起来像真人"。** 另注：作者据此建议"按实拍复刻"，作为策略可以成立（AI 生成的地标不可信，实拍更稳），但那是策略选择，不是事实判断。

**第二个案例（02_南京探店，全批核验补）**：65.2 秒、1080×1920。文档写「真人实拍探店」，工具判 AI 91% + 3D 6% + 实拍 1%，人工又改成了真人。抽 6 帧比对，约 10s 处字幕原文是「**不过我可是数字人**」——片子自己承认了。真实构成是 AI 数字人口播（主体）+ 实拍街巷空镜（过场）。两次修正错的是同一个地方：把"看着像真人"当成了证据。第三次是 `21_襄阳`，同样改了工具判的 100% AI，最后靠三个时点的手部特写才推翻（见 ce24）。

**合成演练（非原片事实，用于演示流程）**：输入一条 45 秒县域宣传片，仅有镜头切分与关键帧、无 VLM。按本卡执行：先出分镜表（12 行），再填画面测量 7 项（无测量工具时按关键帧估读并标"估算"），制作方式列给概率 + ⚠，最后在"不确定点"写"第 4/7/9 镜疑似模板渲染，需目视复核"。预期交付物：一份能让他人不再看原片也能复现镜头数与节奏的报告。

## A2 — 触发情境

**用户会在这些时候需要它**：
1. 看到一条效果不错的文旅片，想知道"它到底怎么拍的"，而不是只想要一句观感。
2. 手里有 `breakdown.json` / `report.md` / 分镜截图，但不知道怎么变成可执行的东西。
3. 要复刻某条片子前，先确认它的结构、节奏、包装规格。
4. 团队要复盘一条已发布片，需要可回查的记录而不是口头总结。

**语言信号**：`拆解这条片子`、`分析这个视频怎么做的`、`逆向拆解`、`这条片的分镜/节奏/包装是怎样的`、`deconstruct this video`、`reverse-engineer this short video`、`break down the shot list`。

**与相邻能力的区分**：本卡只负责"把片子变成报告"；不负责选结构（→ 叙事结构选型）、不负责写提示词（→ 提示词包装配）。若用户直接说"帮我做一条 XX 城市的片子"，不要先拆解，直接进结构选型。

## E — 执行

**输入契约（必需）**
- 视频文件路径，或已有的 `breakdown.json` / 分镜表 / 关键帧目录。
- 视频元信息：时长、分辨率、帧率（缺则从文件读取）。
- 可选：发布平台、是否官方号（影响合规与包装判断）。

**缺失处理**：无视频也无拆解数据 → 停止，索要其一；不得凭记忆编造分镜。

**步骤与判停**
0. **先定制作方式的硬证据**，按三级顺序找，前一级命中就不往下走：

| 级 | 找什么 | 命中即定案 | 实测覆盖 |
|---|---|---|---|
| 一级 画面内文字 | 平台水印（「AI 生成」类）、出品致谢（「由 XX 提供技术支持」）、角色标注、片尾声明、**台词自述** | 是 | 27 片里 11 片（41%） |
| 二级 类型特征 | 动画/游戏引擎/影视 IP 角色/物理不可能（人踩发光物悬空、食物长在花丛里） | 是 | 覆盖另外 9 片 |
| 三级 观感 | 皮肤无毛孔、手部糊块、发丝边缘、光照不一致 | **不能单独定案，只标 ⚠** | 无标识片靠二级支撑 |

一级不限水印：`02_南京` 没有任何 AI 水印，但字幕写着「不过我可是数字人」，同样是硬证据——**台词自述也算一级证据**，别只盯着画面角落。二级里最好用的是**找手**：AI 生成的人脸已经很稳，但举起来的手常常是融合的半透明桨状（无指甲、无指关节、指根连成一片）。`21_襄阳` 就是靠三个时点的手部特写定案的——口型反而不是好判据，实测四个时点嘴形确实在变，别拿它当理由。抽帧时按 12%/37%/62%/87% 取 4 帧做 2×2 拼图看标识，存疑的再抽 6 帧比对同一角色的脸是否漂移（会漂多半是 AI，但不漂**不能**反证是真人——`02_南京` 的数字人就很稳）。

完成标准：每条制作方式判断都能指到"第几秒的什么标识 / 什么类型特征"，或明确写"无标识、无类型特征，判不准"。
1. 读元信息，切分镜头，产分镜表（镜号/起止/时长/景别/机位/运镜/制作方式/置信度/叠加层/转场）。完成标准：镜头数与时长相乘 ≈ 总时长。
2. 判叙事结构：一句话 + 分段（时间段/内容/节奏）。完成标准：能用一句话说清"这片子靠什么串起来"。
3. 统计包装层：字幕句数、花字处数、文字标注处数（含跟随移动数）、贴纸、标题、常驻图层、按台词定位点。完成标准：每类有数字与位置。
4. 测画声音层：有声轨、人声类型、BPM、段落变化次数、音效数与类型、卡点布尔值。
5. 写画面测量 7–8 项；标注口径（"用于写生成提示词，不是拍摄方案"）。
6. 写复刻要点（3–5 条）与不确定点（逐条给补证方式）。完成标准：每条不确定项都能回答"怎么才能确认"。
7. **判停**：若制作方式置信度 < 0.6 → 标 ⚠，并在复刻路线上给两种预案（实拍/混合），不得单选。
8. **交付前跑摘抄校验**：`python resources/check_quote.py <卡片目录> <源文档目录>`。`## R — 原文` 段属设计内引用不计；I / A1 / A2 / E / B 段出现 ≥30 字连续照搬 → 改写，不要加豁免。豁免只留给词表与原句示例，且必须写理由。

**输出契约**
- 十段式 Markdown：结论 / 角色场景 / 叙事结构 / 分镜表 / 剪辑包装 / 声音 / 画面测量 / 复刻要点 / 不确定点 / 产物索引。
- 分镜表为表格，字段齐全；测量项带数值与单位；不确定项带补证方式。

**拆解时顺手记下复刻 QA 的比对基准（借鉴 rea-video 复刻质检，2026-11-25）**：本卡拆出的"分镜表 + 画面测量"不只用于写提示词，还是回传生成片后的逐镜验收基准。拆解时除景别/时长外，为每个镜头补记三项可比对量——①**运镜方向**（推/拉/摇/移，以及移动方向，供验收查是否同向）、②**姿态变化量**（原片是 `anchored_pose` 微动还是有大幅动作，供验收查有无脑补局部特写——ce35 脚丑就是脑补了整条小腿）、③**构图轮廓**（主体占比与位置）。用户回传生成片后的完整 QA 维度与流程见 `SKILL.md` 交付硬规则第 3 条；本卡只负责在拆解阶段把这三项基准记全，不重复验收流程。

## B — 边界

- **不要用**：没有任何参考片、纯原创构思时；只有一句"帮我做条片子"时；用户只要一条即用提示词、不需要体系时。
- **作者警告的失败模式**：把工具的低置信度判断当事实；**反过来也有坑——凭观感把工具的高置信度判断改掉**（01 篇把「96% AI」改成「真人实拍」，02 篇把「AI 91%」改成「真人实拍探店」，21 篇把「AI 100%」改成「实拍短剧」，三条经抽帧核验都是错的，见 ce22、ce23、ce24）；把画面测量当拍摄方案（对 AI 片是"画面里的光影"，对实拍片才是布光）。
- **反例速查**：本卡引用的 `ce` 编号见能力包根目录的 `resources/case-index.md` 末节「反例索引（36 条）」，一句话教训 + 证据等级；16 条是实测（`field-tested`，含 ce26–ce36 用户付费生成实测与成片/转场/原片复盘反馈），其余为文档明示或推断。
- **作者盲点（阶段 0 批判）**：样本全是 2026 年竖屏抖音生态，横屏/长视频的节奏数值不可直接搬；素材到"发布"为止，没有数据反馈环节。
- **结论带保质期**：27 片采样日 2026-11-23。平台流行结构（钩子写法、节奏、槽位顺序）复核周期 6 个月 → 2027-05-23 到期；题材与叙事类型 12 个月；工具能力（能不能出 30fps、参考视频带不带音轨）3 个月。到期**标「待复核」不删**，复核方式写具体（重抽 3 帧确认结构未变 + 查当期热门是否已换 + 同参数复现一次）。
- **易混淆**：`story-structure`（选结构，不拆片）；`prompt-pack`（写提示词，不测量）。
- **共同纪律**：七卡共用一套判定纪律（先测量后动笔 / 结构先定 / 分层不混 / 结果可复核 / 缺料走降级 / 证据分级 / 出彩可指认），全文见 SKILL.md「核心原则」；本卡只展开本域，跨域冲突以那 7 条为准。
